## 根本問題與修復

### 問題：平板無法找到印表機
- **根因：** `proxy.py` 的 `MY_IP = "192.168.0.21"`（舊網段），平板收到探索回應後連不上
- **修復：** 改為 `MY_IP = "192.168.1.109"`，`PRINTER_IP = "192.168.1.124"`

### 問題：兩台平板都顯示「無法連線」
- **根因：** Epson 只允許一條 TCP，一台在用另一台就顯示錯誤
- **結論：** 設定頁顯示「無法連線」是正常的，**實際有訂單時自動連線印出**

### 問題：pi54 也裝了 printer-proxy
- **根因：** 今天部署 fleet 時 pi54 也被部署了 proxy，搶佔了印表機連線
- **修復：** pi54 的 printer-proxy 保持停止狀態

## 圖片截斷 Bug 修復（2026-04-22 下午）

### 問題描述

長收據（11 品項以上）只截到上半段，下半部品項全部漏掉。

**範例：** UE-13487 伯益鄭 實際 $348，但 DB 存成 $185，只有 5 品項。

### 根本原因

ESC/POS 是二進位格式，裁紙指令 bytes 為 `\x1D\x56`。

舊版 proxy 做**字串比對**，但這兩個 bytes 可能巧合出現在圖片壓縮資料中間：

```
收到資料 → 發現 \x1D\x56 → 誤以為印完 → 截圖（只有前半段）→ buffer 清空
後半段資料 → 進新 buffer → 沒有人存它 → 永久遺失
```

短收據（5 品項）資料量小，碰到的機率低；長收據資料量大，必然發生。

### 修法

**改成 TCP 連線關閉（FIN）時才存完整圖片**，確保所有資料收齊再處理：

```
資料持續累積 → 平板送出 FIN → 連線關閉 → 存完整 buffer → OCR
```

### 驗證結果

UE-13487 重新列印後：
- 圖片完整顯示 11 品項 ✅
- GPT-4o 解析：11 品項，$348 ✅

## OCR 辨識錯誤處理策略

### 現況

每次獨立呼叫 GPT-4o Vision，沒有記憶，不會自動學習。

### 已發現的辨識錯誤

| 實際品名 | GPT-4o 誤讀 | 類型 |
|---------|------------|------|
| 活力滷蛋白 | 活力漸蛋白 | 字形相近（滷/漸）|
| 脆脆杏鮑菇 | 脆脆得捲 | 完全錯誤 |
| 豬腱肉 | 豬蹄肉 | 字形相近（腱/蹄）|

### 三層改善方案

**第一層：給 GPT-4o 完整菜單（最有效，待實作）**

在 prompt 中加入所有品項名稱，要求 GPT 從菜單中選最接近的品名，而不是自由發揮。可將誤讀率降至接近 0。

**第二層：錯誤修正字典（補救層，待實作）**

OCR 後自動套用已知的 wrong→right mapping：
```python
CORRECTIONS = {
    '活力漸蛋白': '活力滷蛋白',
    '脆脆得捲':   '脆脆杏鮑菇',
    '豬蹄肉':     '豬腱肉',
}
```

**第三層：人工確認回寫（未來）**

廚房確認時若修改品名，記錄並加入字典，持續擴充。
