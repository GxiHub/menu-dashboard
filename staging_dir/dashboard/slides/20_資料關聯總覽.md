## 3. 現有關聯路徑

```
品項管理 (menu_items)
  │
  ├─── vendor (文字) ─────────── 記錄「現在跟誰叫」
  │
  ├─── acc_ingredient_id ──────→ 食材 (ingredients)
  │                                ├── vendor_id → 廠商 (vendors)
  │                                └── product_code = product_id
  │
  ├─── luwei_product_id ──────→ POS 商品 (products)
  │                                ├── is_available (門市開關)
  │                                └── selling_price
  │                                      │
  │                                      ▼
  │                               訂單明細 (order_items)
  │                                ├── product_id → products.id
  │                                ├── product_name (文字快照)
  │                                └── unit_price, quantity
  │                                      │
  │                                 ┌────┴────┐
  │                                 ▼         ▼
  │                              撿料站     滷鍋站
  │                             (picking)  (braising)
  │
  └─── ingredient_purchases ──→ 進貨記錄
         ├── ingredient_id → 食材
         ├── qty, unit_price, total
         └── date, invoice_no
```

## 4. 三個已知問題

### 問題 A：換廠商 → 歷史失真

```
現在：ingredients.vendor_id = 巨琩
      ↓ 換成同賀
      ingredients.vendor_id = 同賀
      → 過去跟巨琩買的進貨記錄，看起來像是跟同賀買的
```

**解法：** 進貨記錄 (ingredient_purchases) 自己帶 vendor_id，品項只記預設廠商

---

### 問題 B：上下架混亂 — 三個開關各自為政

| 開關 | 位置 | 問題 |
|------|------|------|
| is_available | 品項管理 | 總開關，但 POS 不一定跟 |
| is_pos | 品項管理 | 只記「有沒有同步過」 |
| is_available | POS products | POS 自己的開關，可獨立操作 |

**理想：** 品項管理下架 → POS 一定跟著關；POS 可自己暫時關但不能自己開（品項管理沒上架的）

---

### 問題 C：訂單明細斷裂 — 56% 沒有 product_id

```
全部 order_items：394 筆
product_id = NULL：222 筆（56%）

→ 超過一半的銷售記錄無法追溯回品項
→ 無法精確統計各品項銷量
→ 撿料/滷鍋 靠 product_name 文字運作，不影響操作但無法分析
```

## 5. 目標架構（一間店）

```
vendors (廠商)
  │
  │   menu_items (品項管理) ─── 唯一主檔
  │     │ product_id = 全系統通用主鍵
  │     │ default_vendor_id → 預設廠商
  │     │ 名稱、分類、單位、每份g、每g元、售價
  │     │ 保存方式、備料時間、上架狀態
  │     │
  │     ├────────────────→ POS products
  │     │                   product_id (FK)
  │     │                   is_available（受品項管理控制）
  │     │                   selling_price
  │     │                        │
  │     │                        ▼
  │     │                   order_items
  │     │                   product_id (FK，不允許 NULL)
  │     │                   product_name (快照)
  │     │                        │
  │     │                   ┌────┴────┐
  │     │                   撿料站   滷鍋站
  │     │
  │     └────────────────→ ingredient_purchases (進貨)
  │                         product_id (FK → menu_items)
  │                         vendor_id (FK → 當次進貨廠商)
  │                         qty, unit_price, date
  │
  └── 每筆進貨獨立記錄廠商，品項只記預設值
```

## 6. 修復優先順序

| 順序 | 項目 | 影響 | 難度 |
|------|------|------|------|
| 1 | 進貨記錄加 vendor_id | 換廠商不會覆蓋歷史 | 低 |
| 2 | 修復 order_items 的 product_id | 銷售分析才能用 | 中 |
| 3 | 統一上下架邏輯 | 品項管理作為 single source of truth | 中 |
| 4 | 去掉 ingredients 中間層，進貨直接連 menu_items | 簡化架構 | 高 |
